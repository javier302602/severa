ÍNDICE
I. INTRODUCCIÓN
El presente documento describe la especificación de requisitos del sistema SEVERA, desarrollado tomando como base el informe de Análisis Estadístico de Vulnerabilidades de Seguridad en Software, elaborado por Ángel Paolo Javier Orneta en el curso de Estadística y Probabilidades (UNAS, Ciclo V, 2026-I), bajo la asesoría del Ing. Wilmer Julio Bermúdez Pino.
SEVERA es una plataforma digital orientada a la gestión, análisis estadístico y priorización de vulnerabilidades de software, permitiendo a analistas de seguridad importar datos de la Base de Datos Nacional de Vulnerabilidades (NVD) del NIST, calcular medidas estadísticas sobre el CVSS Score, generar visualizaciones y obtener un ranking de priorización de remediación sustentado en datos y no solo en intuición.
El objetivo principal de este documento es identificar, estructurar, validar y priorizar los requisitos funcionales del sistema, siguiendo estándares reconocidos de ingeniería de software como IEEE 830 e ISO/IEC/IEEE 29148.
Para garantizar la calidad de los requisitos, el proceso aplicado incluye las siguientes fases:
Elicitación de requisitos a partir del análisis estadístico previo y de entrevistas con analistas de seguridad.
Análisis y refinamiento de los requisitos identificados.
Verificación y validación de los requisitos.
Consolidación de requisitos en una línea base.
Priorización y estimación de esfuerzo para su desarrollo.
Asimismo, el documento incorpora mecanismos de trazabilidad, gestión de cambios y control de versiones, permitiendo mantener la consistencia entre los requisitos, los módulos del sistema y los objetivos del proyecto.
1.1 Planteamiento del problema
Las organizaciones enfrentan un volumen creciente de vulnerabilidades de software y recursos limitados para remediarlas. Sin un análisis estadístico riguroso, la decisión de qué vulnerabilidad atender primero suele basarse en intuición o percepciones aisladas, confundiendo con frecuencia "urgente" con "importante", lo que puede dejar expuestas vulnerabilidades realmente críticas mientras se atienden fallas de bajo impacto.
Actualmente no existe una plataforma que integre, en un solo flujo, la carga de datos reales del NVD, el cálculo de medidas estadísticas descriptivas sobre el CVSS Score y la generación automática de un ranking de priorización de remediación. El sistema SEVERA busca cubrir esa necesidad, transformando el análisis estadístico desarrollado sobre 150 vulnerabilidades reales en una herramienta de software reutilizable para cualquier conjunto de vulnerabilidades.
1.2 Objetivos
Objetivo general:
Desarrollar un sistema digital denominado SEVERA que permita registrar, analizar estadísticamente y priorizar vulnerabilidades de software a partir de datos reales del NVD, facilitando la toma de decisiones de remediación basada en evidencia cuantitativa.
Objetivos específicos:
Identificar y documentar los requisitos funcionales del sistema mediante técnicas de elicitación de requisitos.
Diseñar una estructura organizada de requisitos que represente las funcionalidades estadísticas y de priorización del sistema.
Validar y verificar los requisitos obtenidos para asegurar su claridad, consistencia y viabilidad.
Priorizar los requisitos identificados considerando su importancia y el esfuerzo estimado de implementación.
Establecer una línea base de requisitos que sirva como referencia para el desarrollo del sistema.
1.3 Justificación
El desarrollo de SEVERA se justifica en la misma pregunta que dio origen al informe estadístico que lo fundamenta: ¿por dónde empezar cuando todo parece urgente? La estadística descriptiva demostró ser la herramienta adecuada para responder esa pregunta con datos y no solo con percepciones; SEVERA busca llevar esa misma lógica a una herramienta de software que cualquier equipo de seguridad pueda usar de forma recurrente, sin tener que repetir manualmente el análisis estadístico cada vez que aparece un nuevo lote de vulnerabilidades.
Para la Ingeniería de Sistemas, este proyecto tiene valor porque conecta dos disciplinas fundamentales: el análisis estadístico riguroso y la ingeniería de requisitos, mostrando cómo un estudio académico de datos puede convertirse en la base formal para el desarrollo de un producto de software real.

Para el desarrollo de SEVERA se aplicaron las siguientes técnicas de elicitación:
Revisión documental del informe estadístico previo (Análisis Estadístico de Vulnerabilidades NVD), usado como fuente primaria de necesidades.
Análisis de la estructura del dataset real de 150 vulnerabilidades y sus 12 variables.
Revisión de la teoría de CVSS (FIRST/NIST) para definir reglas de clasificación de severidad.
Análisis de plataformas similares de gestión de vulnerabilidades, con fines de benchmarking.

2.3 Validación de requisitos
La validación confirma que los requisitos reflejan correctamente las necesidades de los analistas de seguridad. Se realizó mediante revisión conjunta del equipo, comparando cada requisito contra el problema planteado en la sección 1.1 y contra el contenido real del informe estadístico base.
Revisión de que cada requisito represente una necesidad real del analista.
Discusión y consenso sobre el alcance de cada requisito.
Comparación de cada requisito contra los capítulos del informe estadístico original.
Eliminación de requisitos redundantes o fuera de alcance.
2.4 Refinamiento de requisitos
El refinamiento transformó las necesidades iniciales en requisitos funcionales detallados y estructurados, organizados en 13 módulos y descompuestos en requisitos más específicos cuando fue necesario (ver capítulo VII).
III. DESCRIPCIÓN GENERAL DEL SISTEMA
3.1 Perspectiva del producto
SEVERA es una plataforma digital orientada al análisis estadístico y priorización de vulnerabilidades de software. La aplicación permite a los analistas:
Importar y validar datasets de vulnerabilidades provenientes del NVD.
Calcular automáticamente medidas de tendencia central, dispersión y distribuciones de frecuencia del CVSS Score.
Generar los gráficos estadísticos necesarios para interpretar la severidad de las vulnerabilidades.
Obtener un ranking de priorización de remediación basado en criterios estadísticos.
Generar informes y exportar resultados.
El sistema será accesible mediante aplicación web, permitiendo la interacción entre los analistas y la base de datos de vulnerabilidades.
3.2 Usuarios del sistema

3.3 Suposiciones y restricciones
Suposiciones
Los analistas contarán con acceso a internet para utilizar la plataforma.
El dataset de vulnerabilidades sigue la estructura definida por el NVD (12 variables por registro).
El CVSS Score utilizado corresponde a la versión de Métricas Base de CVSS documentada por FIRST/NIST.
Restricciones

Descripción

Fuente de datos
El dataset inicial depende de la disponibilidad y formato de los archivos del NVD.
Normativa
El sistema debe cumplir con la Ley N.° 29733 de Protección de Datos Personales del Perú.

SEVERA se basa en una arquitectura cliente-servidor de tres capas:

Esta arquitectura permite mantener una estructura organizada y facilita el mantenimiento y la escalabilidad del sistema.
3.5 Comparación con plataformas existentes (Benchmarking)
Se realizó un benchmarking de plataformas relacionadas con la gestión de vulnerabilidades, con el objetivo de identificar funcionalidades útiles como referencia para SEVERA.
Plataformas analizadas
NVD (nvd.nist.gov): buscador y API oficial del NIST; fuente primaria de datos, sin capacidades propias de análisis estadístico o priorización.
CVE Details: portal de terceros que reorganiza información del NVD con fines de consulta rápida, sin análisis estadístico propio.
Tenable / Rapid7 InsightVM: plataformas comerciales de gestión de vulnerabilidades orientadas a escaneo activo de redes, con priorización basada en scoring propietario.
Greenbone / OpenVAS: escáner de vulnerabilidades de código abierto, orientado a detección más que a análisis estadístico descriptivo.

XVII. CONCLUSIONES
El desarrollo del presente documento de Especificación de Requisitos del Sistema (SDS) para el proyecto SEVERA permitió transformar los resultados de un análisis estadístico riguroso de 150 vulnerabilidades reales del NVD en una especificación formal de software, identificando, analizando y documentando de manera estructurada los requisitos necesarios para su implementación.
Durante el proceso de ingeniería de requisitos se definieron 104 requisitos funcionales, organizados en 13 módulos del sistema, y 150 requisitos no funcionales relacionados con rendimiento, seguridad, disponibilidad, usabilidad, precisión estadística y mantenibilidad.
El documento incluye procesos de verificación y validación de requisitos, garantizando que cada uno cumpla con criterios de claridad, consistencia, verificabilidad y trazabilidad, así como coherencia con los métodos estadísticos empleados en el informe original.
La aplicación de metodologías ágiles mediante 13 sprints de desarrollo permitió organizar las funcionalidades del sistema de manera progresiva, replicando en software cada etapa del análisis estadístico original: carga de datos, distribución de frecuencias, medidas de tendencia central y dispersión, visualización gráfica, comparación por categorías y, finalmente, priorización de remediación.
Finalmente, este documento demuestra que un trabajo estadístico académico puede convertirse en la base formal para el desarrollo de un producto de software real, aplicando buenas prácticas de ingeniería de requisitos y estándares internacionales (IEEE 830, ISO/IEC/IEEE 29148).
XVIII. RECOMENDACIONES
Priorizar la implementación de los requisitos funcionales clasificados como Must, por representar las funcionalidades esenciales del sistema.
Mantener activo el proceso de gestión de cambios, garantizando que cualquier modificación en los requisitos sea evaluada, documentada y aprobada antes de ser implementada.
Realizar pruebas continuas de los cálculos estadísticos del sistema contra los resultados de referencia obtenidos en R, para garantizar precisión numérica.
Ampliar el dataset inicial más allá de las 150 vulnerabilidades, incorporando actualizaciones periódicas desde la API NVD 2.0.
Considerar en futuras versiones la incorporación de un módulo de aprendizaje automático para predecir el riesgo de nuevas vulnerabilidades antes de su clasificación oficial.
Validar el framework de priorización con analistas de seguridad reales antes de su despliegue en producción.
